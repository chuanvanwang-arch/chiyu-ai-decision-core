## 1. 现状取证：图写语义在 foundation 无处安放（属实）

CRM 图写（`src/decision/ageGraph.js`）实为可写图：

| 函数 | 操作 | 锚点 |
|---|---|---|
| `addDecision` | `MERGE (n:Decision {decision_id}) SET n.scenario_id=...`（7 字段写顶点） | :95-96 |
| `addParticleVertex` | `MERGE (p:${label} {entity_id}) SET p.name=...`（粒子顶点） | :124 |
| `addEdge` | `MERGE (a)-[r:${rel} {kind}]->(b) SET r.edge_ts`（6 类边） | :149-152 |

承载 **12 个依赖模块**的派生关系（DECIDED_ON / REFERENCED_PRECEDENT / DERIVED_FROM_EXCEPTION / ESTABLISHES_FRAME / OVERRIDES / CAUSED / INFLUENCED）。

foundation 侧现状：

| 面 | 能力 | 真值来源 |
|---|---|---|
| 图**读** | `GraphStore` 只读协议（controlled/out_edges/in_edges/traverse），InMemory/PgCte 只读实现，深度上限 3 + 环检测 | `graph/__init__.py:25-34`；manifest `graph=stable` |
| 图**写** | 无 `GraphStore` 写方法；仅 `OntologyGraph.link(predicate∈K层)`（受控谓词）+ `persist.write_decision_memory_net`（记忆网落库，**非**通用图写） | `ontology/graph.py:79-82` |

**结论**：CRM 的"决策/粒子顶点 + 依赖边"可写图语义，foundation 侧**没有对等的可写协议接缝**。F-02 以新形态复归——非"有无 AGE 等价查询"，而是"**图写语义没地方接**"。此判定**成立**。

## 2. capability manifest 口径（已落地）

`contract/capability-manifest.json` 中 `graph` 条目现状（重生成自 `version.py CAPABILITIES` + `gen_capability_manifest.py`）：

## 3. 替代方案评估（三选一）

| 方案 | 描述 | 优点 | 缺点/成本 | 判据 |
|---|---|---|---|---|
| **A. 受控可写谓词集合** | 复用 `OntologyGraph.link` 的受控判据（谓词∈`profile.predicates` K 层），扩展为可写谓词闭集；CRM 边型映射为受控谓词 | 最小侵入；受控机制已有雏形（graph.py:82 未受控即抛）；与"单源"纪律（graph/__init__.py:13）兼容 | 只支持"有向建边"，无顶点属性 SET；CRM 的 `SET n.scenario_id=...`（7 字段顶点）无法表达；需定义顶点写语义 | 匹配 CRM 边写（6 类谓词），**但不匹配顶点写** |
| **B. 可写协议 `WritableGraph`** | 新增抽象协议：`upsert_vertex(id,label,props)` + `upsert_edge(from,to,rel,props)`，与 `GraphStore` 对等；实现映射到 AGE/CTE | 完整表达 CRM 图写；消费方回捐 Node 等价件可对齐 | **破坏"单源"纪律**（graph/__init__.py:13 禁另起可写图库，否则双写）；需解决与 `persist.write_decision_memory_net` 的单源冲突；新能力入 manifest 触发层守卫连锁 | 功能最全但**架构风险最高**，须走 deprecation/单源裁定 |
| **C. 消费方自建 + 纳入 sanctioned 面** | 图写留在 CRM Node 侧（现状），foundation 登记"图写未提供"；CRM 自建写层，接口经 sanctioned 面回捐 | 零底座侵入；CRM 已有实现（ageGraph）无需迁移；满足试点尽快启动 | 底座侧无图写能力（能力矩阵缺一块）；跨仓语义对齐靠 R2 判据规格兜底 | **短期最优**，与 CRM 建议一致 |

**推荐**：短期走 **C**（图写留 Node + 纳入试点排除面，立即解除 P1 阻塞）；中期评估 **A→B** 渐进（先受控写谓词覆盖边写，顶点写按需升级 WritableGraph，全程守"单源"纪律并走 deprecation 周期）。

## 4. 排期口径

- **当前（0.1.0 冻结）**：图写 = 未提供（manifest 登记 R9 未排期）；CRM 图写留 Node，纳入**试点排除面**（试点验证范围不含图写迁移）。
- **试点期（4 周生产实证）**：CRM 以 Node 现有 `ageGraph` 图写自证；foundation 侧评估 A（受控写谓词覆盖 6 类边型），产出可写谓词闭集草案。
- **1.0 后**：据试点结果决定 A→B 升级；若升级 `WritableGraph`，须走完整 deprecation 周期 + manifest 登记 + 单源裁定（防双写），并同步 R2 判据规格新增写判据。

## 5. 对 CRM 的承诺

1. manifest 已如实登记 `graph` 写能力未提供 + `R9 未排期`（§2，已重生成）；
2. 短期按 C：图写留 CRM Node，不阻塞 P1 试点启动（纳入试点排除面即解除阻塞）；
3. 试点期评估方案 A（受控写谓词覆盖边型），1.0 后据实决定 A→B；全程守"单源"纪律 + deprecation 周期。
