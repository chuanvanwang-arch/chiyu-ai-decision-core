## 1. 缺陷成立：逐项取证（信任-但-核实）

CRM 方投诉的三条证据链，本仓逐一复核**全部属实**：

| # | 投诉 | 本仓取证 | 结论 |
|---|---|---|---|
| 1 | kernel wheel 构建于 09:19:59，源码 registry.py 最后改 09:31:01（晚 11 分钟） | kernel wheel `mtime=09:19:59`；`scenario/registry.py` `mtime=09:31:01`、`api.py` `mtime=09:28:36` | ✅ 属实，wheel 落后源码 ≥11 分钟 |
| 2 | wheel 内 api.py 无 `set_key_format`（源码有 3 处） | 解包 wheel：`grep -c set_key_format` = **0**；源码 `api.py` 含 import + 导出计 3 处 | ✅ 属实，R3 内容未入 wheel |
| 3 | decision wheel 无 errors.py（R8 DecisionError 缺失），仅 13 文件 | 解包 decision wheel：**无 `errors.py`**；`.py` 文件总数 = **13**；源码 `errors.py` 创建于 10:05 | ✅ 属实，R8 内容未入 wheel |

**定性确认**：两个 wheel 均为 **R1（capabilities/09:19 前）之后、R3（set_key_format 09:28/09:31）与 R8（DecisionError 10:05）之前**的中间提交快照。版本号 `0.1.0` 与 `CHANGELOG[0.1.0]`（"首个稳定发行版，含内核抽取至 T31 全部内容"）**声明不符**。

## 2. 契约依据：违背 v1.0 判据 §1 A 类

`docs/release/v1.0-发布判据.md`：
- `:13` 能力清单 29 项，**stable 集合冻结**；
- `:17` BREAKING 必须先走完整 deprecation 周期（先 warn 一版再移除）。

`set_key_format`（R3，键格式可插拨）与 `DecisionError`（R8，决策结构化错误码）已在 **stable 语义集合**内（`version.py CAPABILITIES` 登记）。wheel 缺失二者 = **冻结承诺下的稳定接口以中间态交付**，违反 §1 A 类。此判定**成立**，我方向 CRM 致歉。

## 3. root cause（诚实归因）

- `make dist` 依赖 `check test`（Makefile:42-44），但**未把"构建产物与 `version.py`/门面 `__all__` 同步"设为门禁**；
- R3/R8 提交发生在 wheel 构建（09:19/09:21）**之后**，提交后**未重跑 `dist`**（无自动构建）；
- 结果：`dist/*.whl` 成为"构建时点快照"，与"最新源码/版本声明"脱节。

## 4. 整改承诺（立即执行）

1. **重构建**：在当前 HEAD（含 R1/R3/R8/R4/R6/R2/R5/R9 全部）上重跑 `make dist`，产出与源码同步的 wheel；
2. **纳入门禁**：给 `dist` 增加"产物与源码一致"守卫（校验 wheel 内 `api.py` 含全部 `__all__` 符号、decision wheel 含 `errors.py`），缺则构建失败（`make lint` 级纪律，变异自证）；
3. **版本口径订正**：CHANGELOG 标注 v0.1.0 指 **tag 时点**完整集合，`dist` 仅本地构建产物；消费方以**发布说明声明的 tag/commit** 为准，不以 `dist` 目录时间戳为准；
4. **A 类整改项登记**：本缺陷录入 v1.0 A 类承诺收口清单，作为"stable 集合冻结"的回归项。

## 5. 边界澄清（避免夸大）

`dist/*.whl` 为**本地构建产物**，非本仓 git 跟踪的发布物（git log 不含 dist）。本回执按"交付物与发布说明不符"定性成立处理，并主动澄清消费方实际消费路径：**若 CRM 以 `dist` 目录 wheel 为准，则缺 set_key_format/DecisionError，应以重构建后产物替代**；若以 tag/发布说明为准，则不缺失，本缺陷为构建产物一致性问题。
