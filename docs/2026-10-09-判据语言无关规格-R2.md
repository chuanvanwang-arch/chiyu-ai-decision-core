## 0. 规格元模型（每条判据五段定义）

任何判据的规格必须且只包含五个段，任意实现语言不得增删段：

| 段名 | 类型 | 语义 |
|---|---|---|
| **前置条件 (precondition)** | 合取谓词 `P₀` | 判据**被激活前的系统不变量**；不满足则判据不适用（跳过，不得误判绿）。 |
| **触发输入 (trigger)** | 输入谓词 `T` | 使判据进入"待验证"状态的具体输入形态。 |
| **失败语义 (failure)** | 输出谓词 `F` | 判据被破坏时**必须暴露的失败信号**（异常类型 / 退出码 / 受限标记），消费方可观测。 |
| **变异自证方法 (mutation)** | 操作程序 `M` | 如何制造"判据被破坏"的最小差异，验证守卫确实转红。 |
| **验收判据式 (acceptance)** | 形式谓词 `A` | 判据通过 ⟺ `A` 为真；任何语言实现的等价件必须使 `A` 保持同值。 |

**同一性铁律**：两条判据若"验收判据式 `A` 逻辑等价"，即在任意实现语言下 `A` 真值相同，则视为同一判据；与变量名、异常类命名、代码结构**无关**。CRM 回捐 Node 实现时按 `A` 而非按 Python 源码逐行对齐。

## 1. 判据 K-01：决策场景键**单一注册**（F-05，`register_scenario` 重复登记即抛）

- **Python 真值来源**：`chiyu_kernel/scenario/registry.py:197`（`raise ScenarioRegistryError(...)"决策场景键已注册（单一事实源，禁止重复）"`）。
- **前置条件 `P₀`**：触发键 `k` 满足注册表当前活动的键格式约束（kebab/none 可插拔由 R3 的 `set_key_format` 决定）。
- **触发输入 `T`**：对同一键 `k` 连续调用登记两次（第二次与第一次 `k` 字符串相等，且两次都通过键格式校验）。
- **失败语义 `F`**：第二次登记**必须抛**注册失败异常（不得覆盖、不得返回成功、不得以 `ok=false` 静默吞掉）；异常须机器可判别（带错误码或异常类型可 instanceof 判别，禁仅依赖中文消息文本）。
- **变异自证方法 `M`**（双向，择一即可）：
  1. 把"重复 → 抛"改为"重复 → 覆盖"（`_REGISTRY[k] = profile` 静默替换）；
  2. 把"重复 → 抛"改为"重复 → 返回已存在对象"（幂等静默）。
  两种变异都须使守卫测试转红。
- **验收判据式 `A`**：
  ```
  A(K-01) := ∀ k. register(k) 成功 → register(k) 抛"已登记"错误
  ```
  即：同一键第二次登记必然失败，且失败可被 catch 以**结构化方式**识别。

## 2. 判据 K-02：门面**全量覆盖**（F-06，`__all__` 符号不漏暴露）

- **Python 真值来源**：`tools/check_facade_coverage.py:43 missing_names`——返回某层 `__all__` 里**未被门面暴露**的符号；`main:83` 收集，`sys.exit(1)` 当非空。
- **前置条件 `P₀`**：受检层的 `__all__` 非空；门面（`api.py`）已 import 各层。
- **触发输入 `T`**：注入一个"层 `__all__` 声明了、但门面 `__all__` 未声明"的符号（含改名表映射后仍未暴露的情形）。
- **失败语义 `F`**：门禁**必须以非零退出码**失败（≥1），且输出中列出缺失符号名；**不得**经管道隐藏退出码（`| head` / `| grep` 后仍须传播原退出码）。
- **变异自证方法 `M`**：
  1. 从层 `__all__` 增一个门面未暴露的新符号（漏暴露）；
  2. 从门面 `__all__` 删一个层已声明的符号（多余声明）。
  两路中任一路都须使门禁退出码转 1。
- **验收判据式 `A`**：
  ```
  A(K-02) := (∀ sym ∈ layer.__all__ : sym ∈ facade.__all__)  且  门禁退出码 = 0
  ```
  即：门面 `__all__` 是各层 `__all__` 的**上超集**（可含额外别名/改名），且工具以**退出码**而非仅打印来裁决。

## 3. 判据 K-03：零残留词表 **grep 命中即失败**（F-08，`check_zero_residue.py`）

- **Python 真值来源**：`tools/check_zero_residue.py:45/63`——对 `zero_residue.tokens`（一行一词，`#` 注释）逐 token 扫描目标路径，命中即收集；`main:74` `sys.exit(1)` 当 `hits` 非空。
- **前置条件 `P₀`**：词表文件存在且非空；若词表缺失/为空，工具**不得**静默放行（须告警，见 K-03b）。
- **触发输入 `T`**：目标路径内存在与任一 token **逐字匹配**（子串命中）的文本。
- **失败语义 `F`**：命中 ≥1 ⇒ **非零退出码**；输出须列出命中文件与 token；退出码不得被管道吞掉。
- **变异自证方法 `M`**：
  1. 在受扫文件注入一个词表 token（如注释行）⇒ 退出码转 1；
  2. 把词表文件清空/改名 ⇒ 必须告警（防"空词表 = 全绿"假象）。
- **验收判据式 `A`**：
  ```
  A(K-03) := (∃ tok ∈ tokens, ∃ file : file 含 tok) ⟹ 退出码 = 1
  A(K-03b):= 词表缺失或空 ⟹ 工具以非零或显式告警提示（不得全绿）
  ```
  即：只要词表命中，门禁必然红；词表自身失效也必然被察觉。

### 3.1 K-03 的版本化补充（关联 R7，未在本文展开）
K-03 的 token 集合本身须有**版本号与发布/同步机制**，否则两仓词表各自演进后漂移（R7 要求）。本文档第 1-3 节的规格与 R7 版本化在"判据真值"上同源：`zero_residue.tokens` 是 K-03 的**数据形态**，其版本化由 R7 交付。

## 4. 判据 K-04：决策脊柱**顺序即语义**（run_spine S1 缺上下文 ⇒ 失败，关联 R8）

- **Python 真值来源**：`chiyu_decision/spine.py:69`——`if not context: raise DecisionError("ENGINE_FAULT", …)`（R8 已从泛型 `ValueError` 升级）。
- **前置条件 `P₀`**：决策场景 profile 的 SPINE_ORDER 符合契约顺序（S1_context 位于链首）。
- **触发输入 `T`**：调用 `run_spine` 且触发上下文（`context`）为空/缺失；或 profile 顺序被重排。
- **失败语义 `F`**：必须抛**带机器可路由错误码**的异常（错误码属**闭集**，见 K-04b）；默认语义 **fail-closed**（输入非法不得静默降级）。
- **变异自证方法 `M`**：
  1. 把 `raise DecisionError("ENGINE_FAULT", …)` 改回泛型 `ValueError`）⇒ 守卫测试转红；
  2. 把"空 context 抛"改为"空 context 静默放行"⇒ 守卫测试转红。
- **验收判据式 `A`**：
  ```
  A(K-04) := 空输入 ⟹ 抛异常 且 异常.code ∈ DECISION_ERROR_CODES
  ```
  即：非法输入必然失败，且失败**可用错误码路由**（不依赖 message 文本）。

### 4.1 K-04b：错误码闭集
```
DECISION_ERROR_CODES := {ENGINE_FAULT, UNKNOWN_SCENARIO, DIM_MISMATCH, CONTRACT_VIOLATION}
```
错误码为**只增不改**闭集；消费方按 `code` 路由（禁止按 message 匹配）。跨语言迁移时错误码语义同名对齐（CRM T0 已采用同名编码）。

## 5. 回捐验收与同强度确认

CRM 实现任一判据的 Node 等价件后，以下三者**同时成立**即确认"同强度"：

1. **验收判据式 `A` 逐条为真**（按第 1-4 节的谓词，在 Node 环境跑等价测试）；
2. **变异自证**：按各判据 `M` 段制造破坏性变异，等价守卫测试**全部转红**，还原后复绿；
3. **失败语义可观测**：Node 等价件的失败信号（错误码/退出码）与规格 `F` 段一致，且**不过管道吞退出码**。

> 回捐形态：CRM 产出的 Node 判据实现 + 各自变异自证记录，作为"判据移植"范式。底座侧复核以本文档 `A` 谓词为准，不逐行对拍代码。
