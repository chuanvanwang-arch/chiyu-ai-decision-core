## §0 概念定调

**AI 原生平台 = 决策智能平台** —— 不是低代码 CRUD 平台，而是一套**可编程的决策基础设施**：

- **普通平台管数据**（增删改查）；**本平台管裁决**（怎么做有依据的决策）。
- 用**粒子建模**沉淀企业领域模型（SKILL #3），用**写库即构建**让知识随数据自生长（#1），用**双轨记忆**留住决策上下文（#2），用**九尺子决策脊柱**产出可审计的裁决，用**复盘闭环**让平台越用越准（#8 #9），用**免代码扩展**让客户自主生长（#7）。
- K-M-D 三层管道与双模同源贯穿始终。
- **客户买的不是软件，是决策能力本身；且这份能力随使用而升值（自进化）**。

锚点：本定调与《2026-09-20-10SKILL底座真实落地审计.md》的能力骨架一致；与底座 L0 契约（零领域字面量、消费方注入取值）一致。

## §1 四层架构（概念模型）

```
┌─────────────────────────────────────────────────────────────┐
│ L3 应用与场景层     免代码门户（NL→Schema→渲染，#7）          │
│                     业务应用组合（粒子装配+决策能力挂载）      │
├─────────────────────────────────────────────────────────────┤
│ L2 决策智能内核     K-M-D 三层决策管道　　　　　★最核心       │
│                     ┌─────┐  ┌─────┐  ┌──────────────┐      │
│                     │ K   │→ │ M   │→ │ D 决策脊柱    │      │
│                     │知识  │  │记忆  │  │ S1→S5　　　　 │      │
│                     └─────┘  └─────┘  └──────────────┘      │
│                     双模同源投影（图图谱 + 故事线　　　　）    │
├─────────────────────────────────────────────────────────────┤
│ L1 智能体团队       多智能体编排（#6）｜复盘智能体（#8）       │
│                     反馈闭环回接（#9）                         │
├─────────────────────────────────────────────────────────────┤
│ L0 底座             粒子契约（#3）｜事件总线（#8）            │
│                     审计链（#10）｜PG+pgvector 单源存储        │
└─────────────────────────────────────────────────────────────┘
```

设计意图：

1. **L2 是灵魂**：K→M→D 是**单向证据管道**，不是并列功能。决策要证据（K）、要上下文（M）、要有依据的裁决（D）——这就是「管道」二字的分量。
2. **L1 不替代决策，服务决策**：编排（#6）把任务派给合适智能体；复盘智能体审视决策质量、产出参数处方（#8）；反馈闭环把业务结果回接为下一轮优化的输入（#9）。这是「自进化」的引擎室。
3. **L0 承诺可扩展性**：粒子类型/谓词由消费方注入（#3）、事件总线支撑领域演进（#8）、审计链保证「平台说它是真的，可独立验证」（#10）。
4. **L3 是交付形态**：客户不写代码，用受控声明（schema）组装页面与场景。**免代码的边界是 Schema，不是 LLM 直出 HTML**（#7 铁律）。

## §2 决策脊柱：主链机制

**锚点**：`packages/chiyu-kernel/src/chiyu_kernel/contract/decision.py`（L0 单一事实源）。

- `SPINE_ORDER` 为 **6 步不可重排**：

  ```
  S1_context → S1_derive → S2_score → S3_aggregate → S4_redline → S5_persist
  ```

- **S1_context / S1_derive**：接收触发上下文 → 本体分级，识别决策候选。**约束：S1 先于一切**；跨区/互斥/强主体冲突在此只「剔候选」，不算红线（红线是 S4 的事）。
- **S2_score**：八要素 + 九尺子评分。八要素（`EIGHT_ELEMENTS`）= intent / assumptions / inference / viewpoints / impact / risk_register / stop_loss / concept_refs。⛔ 不得降级为叙述留痕——每个要素要有可复算判分依据。
- **S3_aggregate**：按外置权重配置加权聚合。**`confidence` 唯一来源 = 九尺子 `rubric["ratio"]`**（`CONFIDENCE_SOURCE_KEY="ratio"`），禁止以匹配分 `fused` 冒充。九尺子九键：clarity / accuracy / precision / relevance / depth / breadth / logic / importance / fairness（0–4 整数，`RUBRIC_SCALE_MAX=4`）。⛔ scores 混合时须 `SCALE_KEYS` 逐项判齐，禁 `len(scores)==N` 草率判定。
- **S4_redline**：**链末硬闸门**（不可前置、不可跳过）。自主放行判据为一整行（`AUTONOMOUS_GATE_EXPR`）：
  `autonomous_release = (not redline_hit) and confidence >= autonomous_threshold`，阈值缺省 **0.79**（`AUTONOMOUS_RELEASE_DEFAULT`）。命中红线 ⇒ 强制人工处置 + 屏蔽自主放行；不得短路在相似度之前。
- **S5_persist**：裁决 + 证据链落库（图谱/记忆/决策同库），只写事实不写修饰；每个裁决带 `decision_id` 可回查可复算；落库后触发复盘闭环。

⛔ 历史教训（demo 时序守卫记录）：① 九尺子评分晚于落库 ⇒ 置信度算完即搁置；② 红线短路在相似度之前 ⇒ 八要素与九尺子不参与判定。顺序是契约第一等公民，不得以「性能优化」为由重排。

## §3 记忆与双模

### 3.1 记忆系统
- 双轨：`log` 事件流（append-only）+ `note` 结论（可 upsert/蒸馏）。
- 记忆寻址：六元组（`MEMORY_ADDRESS_KEYS` = topic / layer / anchor_kind / anchor_id / actor / occurred_at）；来源标记 `PROVENANCE_SOURCES`（explicit / payload / default / fallback）；**双时钟分离**（业务时间 `occurred_at` vs 写入时间 `created_at`）。
- 完整性判据：**七维**（`SEVEN_DIMS`）= identity 身份 / structure 结构 / semantics 语义 / time_config 时间配置 / decision_history 决策历史 / operational_state 运行状态 / governance 治理——每维必须有正向证据才 `ok=True`；`hits=0` 合法 vs `hits=None` 缺失（demo：`memory/seven_dims.py`）。
- 记忆提升 → 决策质量回接（#2 铁律）：记忆服务于决策，不是孤立存数据。

### 3.2 双模同源
- 同一事实、两种投影：**图谱视图**（关系/结构/因果连接）+ **故事线视图**（L0–L6 时序/证据演化）。
- 同源可审计：两视图交叉验证，证据可复算。demo 落点：`context/timeline.py` + `pipeline.py`；决策类必须挂 `decision_id`（只读派生绝不落库）。

## §4 自进化闭环（#8 + #9）

### 4.1 复盘智能体（#8）
- 职责链（demo：`RETRO_SKILLS`）：method-cluster-diagnosis → cause-consistency → param-tuning → self-consistency。
- **处方单一事实源**：`(点号键, from, to, status)`（demo：`decision/pool.py`）——一个处方一个动作。
- 三闸门：① sample 闸（抽样带内复盘）② gain 闸（有增益才出方，否则 pass）③ step 闸（小步调优，一步一验证）。
- 护栏：`retro_cfg` 单一事实源；冷却 fail-closed；预算 + 熔断（计数只在 complete/reset/unblock 清零）；**三独立 pass**；`report.py` INSERT-only。
- ⛔ **复盘智能体只报不动**：人工处置两腿裁决；AI 产出处方报告，参数变更必经人工批准（HITL）+ 三独立验证才物化。
  > ⚠️ **本条已于 2026-09-22 按 §12 修订为「异步人工」**（不再在线阻塞）：夜间窗内由自主通道完成出方→影子重放→事务应用，
  > 人工接触点后移至**次日报告批量处置 + 一键回滚**；**红线命中项与阈值放宽项仍挂起，不自动应用**。
  > 修订依据与条件见 §12.5 / §12.7（追认记录）；在 §12 语境外，本节原文仍作历史条款保留。

### 4.2 反馈闭环（#9）
- 裁决 → 业务执行 → 结果回流（成/败/偏差）→ 存入记忆成为下一轮证据。
- 北极星指标 + 埋点：决策质量可度量；evaluator 闸门：效果不达预期 → 处方回滚。
- 语义闭环：`裁决 → 结果 → 记忆 → 复盘 → 处方 → 参数 → 更准的裁决`。
- ⛔ 自进化不等于失控：所有参数变更走「人工批准 + 三独立验证 + 熔断」。

## §6 私有化交付下的用户/权限收敛

- 交付形态：**私有化单租户**（用户已确认）。
- 收敛方案：多租户模块**不引入**；收敛为 **组织 → 项目 → 角色** 三级 RBAC。
- 每个项目绑定一个 `TenantProfile`（L4 注入：粒子类型、谓词、红线事项目录、评分配置）——同一内核、不同领域配置，即"换领域不改内核"。
- 动作面是权限边界：写操作带闸（R1–R6 分级守卫 + HITL 确认），智能体写操作经动作面统一走审批，可审计可回滚。

### 12.3 使"无人值守"可生还的工程前提（**这些不是审批闸，是正确性闸**）

B 档去掉了人工审批，因此下列机制**反而更不可省**：

1. **影子重放**：应用前用历史样本 dry-run，重算公式须与运行引擎**逐字对齐**（非"语义相近"）。
   ⛔ 无重放的变更 = **blind patch** —— 线上劣化只能靠事后发现（`SKILL.md:260`）。
2. **拒绝出方守卫优先于出方规则**：样本量 / 知识覆盖率未达门槛时**不出任何处方**，守卫命中即短路。
   ⛔ 小样本噪声被固化为"经验"后难以回滚，是**进化腿最常见的事故源**（同处）。
3. **处方应用必须事务原子**：配置写入与处方状态迁移同一事务，要么全成要么全败；
   否则残留「配置已改、处方仍待批」半应用态，污染运行态且无法自动收敛（同处）。
4. **预算 + 熔断 + 冷却**（均已有）：`total_deadline_ms` / `llm_fail_circuit` / `cooldown_days`，
   且 `0` 表示**显式关停**而非"没配"（关停事实须随运行结果上报，不静默）。
5. **全链审计 + 一键回滚**：`audit/chain.py` 的 `build_chain`/`verify_chain`（SHA-256 链式）为每次
   自变动作建证据链；回滚 = 逆动作，同样留痕。
6. **verdict 契约机器可读**：纯方法论执行**默认不抛异常**，用"没抛错"判成功是**假阳性**；
   须显式输出 `{verdict: pass|reject}`，**fail-safe 默认保守**（异常 / 缺 verdict 一律按拒绝挂起）。
7. **幂等 + 系统锚**：夜批沿用 `derive_idem_key` 与 `system_anchor("nightly:<reason>")`，防重跑与锚点漂移。

### 12.4 风险登记（B 档下**必须**被显式承认的四条）

| # | 风险 | 触发条件 | 已声明的后果 |
|---|---|---|---|
| R1 | **自我扩权（最严重，B 档特有）** | 平台自动**下调** `autonomous_threshold` ⇒ 解锁更多自动化 ⇒ 再次下调 | 自改系统可把 HITL 静默架空，且每一步单独看都只是"一次小步调参"。**B 档把自主权推到最大，故本风险在此档最尖锐** |

- **`ai-*` 基线目录与 L0 契约目录对自主写入通道物理只读** —— 一次性拆掉 R2 与 R3 的一部分。

## §13 对外披露纪律（硬约束 · 2026-09-22 新增）

> 用户指令（2026-09-22）：**设计文档不得出现权属类敏感字样；产品展示页面更不得体现
> 内部核查矩阵等尚未公开的要素**。本条不是文案偏好，而是**披露边界**——相关知识产权处于
> 申请/待申请状态，**申请日前公开对应术语会损害可授权性**。

### 13.1 四层披露面（「页面看不到」是幻觉）

| 层 | 位置 | 是否对外 | 处置 |
|---|---|---|---|
| ① 渲染串/静态资源注释 | 门户 HTML / JS（`curl /static/*.js` 即全量可见） | ✅ 是 | 必清 |
| ② 后端字面量 | API 错误消息、校验提示、**raise 消息**、seed 数据 | ✅ 是（随响应上屏） | 必清（最高优先） |
| ③ 源码注释 / docstring | `packages/**/*.py` | ⚠️ 交付/参赛/开源即暴露；且 **docstring 会编入 `.pyc` 常量池** | 必清 + **强制重编译** |
| ④ 设计文档 / 计划 | `docs/**/*.md` | ⚠️ 随评审稿、投标材料、参赛包外流 | 必清（本条指令的直接对象） |

### 13.2 禁用清单与替代表述

| 禁 | 替换为 | 说明 |
|---|---|---|
| ⛔ **权属术语 + 其代号组合**（指代它们的任何后缀形式："○件" / "条款序号" / "实施口径序号" 等亦在内） | `自研规范` / `裁决主链规范` / `主链时序` / `红线条款` / `内置骨架` | **替代表述只保留功能性语义**；具体 token 清单见**内部便签** `.workbuddy/disclosure-denylist.md`（本地排除、**不入仓**） |
| ⛔ **内部核查/评分要素**（七边×七维核查矩阵、评分尺子分项、与其同现的分级标签） | 展示页**不出现**；对外只说"可审计的裁决依据"，举证走**受控导出**，不由页面直接渲染 | 这是本次点名的重点：⛔ **门户/看板/演示页一律不得把这些内部要素作为 UI 卖点或可视化对象** |
| 内部代号 / 仓库内部路径 | 严禁出现在对外面 | 内部代号一律先用中性名再对外；路径不外露 |

### 13.3 三条执行铁律

1. **清 upstream，不清 downstream**：发现展示面有敏感字样 ⇒ 先从渲染串/API 消息/契约常量里删，
   **不许**只在页面上盖一层 CSS 或用前端文案遮蔽（HTTP 响应仍能取到原文）。
2. **一次到位，不留半成品**：任何新页面/新接口进入受控发布前，跑 §13.4 的零残留检查；
   它不是一次性的，要能**重复执行**。
3. **改 `contract/*.py` 必须重生成 `contract/manifest.json`**（`make manifest`）。
   ⚠️ 实测：本次仅改注释即触发 `test_contract_manifest::test_manifest_matches_disk` 红灯 ——
   这条守卫**真的能抓到**「契约文件内容变了」，是本项目少见的诚实闸门，不得跳过。
