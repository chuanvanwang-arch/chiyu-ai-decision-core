## 0. 一句话结论

APS 是 chiyu-foundation 的**正确消费范本**（决策脊柱端到端消费、`is` 身份断言 + 打桩判别力测试锁死防漂移），
但蓝图落地后暴露出**新的债**：底座把"领域注入 / 决策落库 / 审批闸 / MCP 骨架"都做成了稳定子集，
而 APS 有三处仍在**平行自建**，一处**引用了已失效的拒绝理由**，一处**护栏通电缺口**。
⇒ 本轮建议的核心不是"补功能"，而是**把重复自建收敛到基座、把护栏真正通电**。

## 2. 新增建议（Add）—— 底座已就绪，APS 缺的接线

### A1【最高杠杆】把域注入收敛到基座 `inject_domain`（WS6）
- **现状**：APS 域取值散在 `schema.py`（19 属性类型 / N 粒子类型 / 受控谓词），自建注入。
- **建议**：用基座 `inject_domain(profile=..., actions=..., scenarios=...)` 作为**唯一域注入闸**，
  APS 侧只保留"取值填充"，删除自建注入机制。
- **验收判据**：故意把某粒子类型写进基座 `TenantProfile` 缺失位 → `inject_domain` 抛
  `DomainInjectionError`；若不抛红则探针无判别力（须变异自证）。

### A2 决策落库改用基座 `PgVectorStorePersister` + `write_decision_memory_net`（WS2）
- **现状**：`decisions.py:99-270 record()` 自建落库 + 手写 7 边
  （`OVERRIDES / DERIVED_FROM_EXCEPTION / ESTABLISHES_FRAME / INFLUENCED` + kmd 的 `DECIDED_ON`）。
- **建议**：S5_persist 改注入基座 `PgVectorStorePersister.persist(...)`，七边写入交给
  `write_decision_memory_net`；APS 保留"域特有落库字段"（phase/human_signal/context_snapshot）。
- **验收判据**：故意注入一条红线决策 → 基座 `judge_worthiness` 拦正向边（只落 event 不写边），
  APS 侧断言随之变化；若无拦截即探针假绿。

### A3 `kmd_spine()` 注入红线闸 + 审批闸（WS3）—— **把"声明了却不拦"变成"真拦"**
- **现状（实测断点）**：`__init__.py:200`
  `return KmdSpine(self.store, decisions=..., context=...)` —— **不传 redline**；
  `sched-kmd-decide`（`:813`）亦不传 ⇒ `redline=None` ⇒ S4 红线闸**恒不命中**。
  同时 `evaluate_redline` 已在 `foundation.py:158` re-export 却**无人注入域红线**。
- **建议**：
  1. `kmd_spine()` 增 `redline=<APS 域红线回调>` 形参并接上；
  2. 若需人工放行，注入基座 `DecisionApprovalGate`（红线命中即强制 HITL，不因置信度高豁免）。
- **验收判据**：投一条**必命中域红线**的决策 → S4 拦截 + `autonomous_release=False`；
  再投打桩（把红线回调改恒 False）→ 断言随之变化。**变异自证必做**。

### A4 `dispatch` 接入 `security.require()` —— 安全从"可用"变"生效"
- **现状**：`security.py` 三档 `off/advisory/enforced` **默认 off**（`:59 SECURITY_MODES`、`:230`）；
  权限矩阵 / 角色 / 命名空间齐备，但 `ActionRegistry.dispatch`（`actions.py:671-735`）
  **全程无 `security.require()` 调用** ⇒ 权限**声明了却不拦**。
- **建议**：在 `dispatch` 内、写入闸之前接 `security.require(...)`；灰度
  `off → advisory（观测 would_deny 命中率）→ enforced`，并把命中率纳入运维指标。
- **验收判据**：`enforced` 模式下 analyst 触发 `write` Action → 抛 `PermissionDenied`；
  切 `advisory` → 放行但 `would_deny=True`。

### A5 落地一个传输层（**基座仅有协议抽象，transport 须消费方自实现**）⟦rev⟧
- **现状**：`ActionDef.surfaces` 含 `mcp`（声明），但 APS 仓库内**无任何 transport 实现**。
- ⟦rev⟧ **前提更正（APS 回信指出，本仓已确认）**：基座 `mcp/__init__.py:4-5` 原文
  「网络型 transport（stdio / Streamable HTTP）不在本阶段——`McpTransport` 为协议，
  真实 transport 可后续实现；测试用 `InMemoryMcpServer` 替身。」
  ⇒ 基座给的是**协议 + 内存测试替身**，**不是可对外服务的 transport**；
  故本项是"**自实现 transport + 接线**"，**不是**接线活。
- **建议**：APS 自实现 transport 并包住 `dispatch`（第 0 闸 + 安全 + schema 校验 + 审计）；
  是否等待基座排期见 APS 反向请求 R7（foundation 侧待确认）。
- **验收判据**：外部调一个 `needs_approval` Action → 未带 approval 不放行；审计链有记录。

## 3. 删除建议（Delete）—— 平行自建 / 已失效 / 冗余

### D1 删除 APS 对 `PgVectorStore` 的"整装不采纳"决定（**理由已部分失效**）⟦rev⟧
- **原判断（已修正）**：`foundation.py:32-33` 拒绝整装 `PgVectorStore`，列三坑：
  ① `upsert_particle` 硬编码 `dim=1024` ② `connect(dsn=)` 绕过 `validate_dsn` ③ env 键名不可注入。
- **实测复核（APS 回信纠正，本仓确认）**：
  -① **已修**（`store/pg_store.py:88-90`，`dim` 可注入，默认 `VECTOR_DIM`）；
  - ② **已修**（`:43-46`，schema 可注入）；
  - ③ **未修**（`store/dsn.py:19-24` 仍为模块级常量 `DSN_ENV` / `SCHEMA_ENV` / …）。
- **修正后建议**：不采纳结论**降级为条件性** —— ①②已修使整装采纳成为可能，
  ③未修则维持自实现 store；**请同步标注第③条未修**，避免其他消费方误判为"三坑全修"。
  （对应 APS 反向请求 R2：③解决后 APS 重新评估整装采纳。）

### D2 删除 APS 自建的部分落库/注入机制（随 A1/A2 收敛）
- 随 A1/A2 落定，删除 APS 侧重复的域注入机制与七边 writer，保留域特有字段逻辑。
- ⚠️ **纪律**：删除前须逐条确认基座等价物已覆盖（含降级留痕、contentHash 幂等），
  不可"看着重复就删"。

### D3 删除自建 `aggregate_confidence` 口径债（若蓝图已补导出）
- **现状**：`foundation.py:160-164` 登记基座门面**未导出** `aggregate_confidence`，
  APS 改用 `score_rubric(...).ratio` 作唯一置信度来源（`kmd.py:455-459`）。
- **建议**：蓝图若已补门面导出 ⇒ 切回基座口径并删除该债注释；若仍未导出 ⇒ 保留现状（不绕过门面）。

- 现状：`schema.py` 有 8 条受控边声明未接线。**建议**：要么接线，要么从"可接线"移出，
  避免契约本身成为假绿源。

### U3 记忆真向量通道（`memory.py:608` hash_signature_inline → pgvector）
- 现状：dense 通道为**离线哈希签名**（确定性、零外部依赖），非语义 embedding。
- **建议**：接基座 `PgVectorStore` 真向量召回；过渡期保持"哈希=兜底、显式 degraded 留痕"。

### U4 `autonomous_threshold` / `off` 默认纳入治理面
- `security.py` 默认 `off`、`autonomous_release` 默认阈值硬编码 ⇒ 建议：按域可调 + 审计留痕，
  生产默认 `advisory`，禁止长期 `off`。
