# 接口参考版本联动说明

> 日期：2026-10-13 ｜ 配套：`docs/release/v0.1.0-接口参考.md`（人类可读层） + `tools/gen_interface_reference.py`（机器可读层）
> 目的：把"接口参考 ↔ 版本"的联动从口头约定落到**可机检的 manifest**，每次发布可 diff 对账。

---

## 1. 联动架构（两层）

| 层 | 产物 | 性质 | 权威度 |
|---|---|---|---|
| 机器可读层 | `docs/release/interface_reference.manifest.json` | `tools/gen_interface_reference.py` 生成，带版本戳 + 逐符号签名 | **计数权威**（发布对账用） |
| 人类可读层 | `docs/release/v0.1.0-接口参考.md` | 同源自 `__all__` 机械提取 + 人工策展"说明"列 | 阅读用，说明列人工维护 |

- manifest 头带：`package_version` / `api_version` / `contract_version` / `__version__` / `generated_at` / `source`（固定为 `packages/*/src`，非 wheel，避免版本混用）。
- markdown 参考的"说明"列由人工维护，**不**由生成器覆盖；发布时以 manifest 计数为权威对账。

## 2. 当前发现的版本错位（须处理）

1. **文件标签 vs 实际版本不符**：`v0.1.0-接口参考.md` 标题写 `v0.1.0`，但当前 `API_VERSION=1.0.0` / `CONTRACT_VERSION=1.0.0`（`version.py:56/59`）。建议该参考头部显式携带 `API_VERSION`/`CONTRACT_VERSION`（而非硬编码 0.1.0），或发布时按版本重命名。
2. **计数已漂移（stale）**：参考文档标注 `chiyu_kernel.api` 导出 **380** 个；当前实取 **407** 个（差 27）。根因：T68 的 E9+X2（contract 再导出 approval 五符号 + api 再导出 `AUDIT_EVENT_*` 三常量）未同步回生成。其余门面：contract 文档未单列、approval 5 / decision 15 / portal 26 与 manifest 一致。
3. **manifest 已就位**：本次生成 `interface_reference.manifest.json`，`total_listed=525`（含门面间再导出重叠），去重唯一值见《逐符号成熟度映射表》= 499。

## 3. 生成与对账命令

```bash
# 生成 manifest（写 docs/release/interface_reference.manifest.json）
python tools/gen_interface_reference.py

# 仅校验（CI 用，不写文件）
python tools/gen_interface_reference.py --check
# 输出示例：CHECK total_listed=525 api_version=1.0.0
#          chiyu_kernel.api: 407  chiyu_kernel.contract: 72  ...

# 消费方可机检：读取 manifest 断言门面符号集合
python -c "import json; d=json.load(open('docs/release/interface_reference.manifest.json')); print(d['facades']['chiyu_kernel.api']['count'])"
```

**发布流程（建议钉进 Makefile / CI）**：
1. 改 `version.py` 的 `API_VERSION`/`CONTRACT_VERSION` → 重建 wheel；
2. 跑 `python tools/gen_interface_reference.py` 重生成 manifest；
3. diff manifest 与上一版，确认无意外符号增减（意外增减 = 门面守卫 `test_facade_import_vs_all` 应已拦截，此处为二次对账）；
4. 据 manifest 计数刷新 `v0.1.0-接口参考.md` 头部版本戳与各门面"导出符号 N 个"；说明列按需人工补。

## 4. 与能力矩阵的联动

- manifest 的"符号 → 源模块"可映射到 `chiyu_kernel.version.CAPABILITIES` 29 能力层（见《逐符号成熟度映射表》的同款推导），从而把"每个符号的成熟度"也版本联动到 `CAPABILITIES`。
- `require_capabilities(...)` 启动闸（G5）已消费 `CAPABILITIES`，与 manifest 同源，发布时一并校验。

## 5. 已知缺口（RFE 候选）

- **portal 未单列能力层**：`portal` 整面不在 `CAPABILITIES` 29 层内，《逐符号成熟度映射表》标为"未登记(面sanctioned·非能力层)"。建议补登 `portal` 能力层，使版本联动覆盖完整。
- **参考文档无生成脚本历史**：此前 `v0.1.0-接口参考.md` 由人工从 `__all__` 提取（头部自述"机械提取"但仓内无对应生成器）；本 `gen_interface_reference.py` 补齐该缺口，今后以脚本为准。
