## §3 【回答问题 #1】10 SKILL 的分层归类

### 3.1 关键论断：10 SKILL 一个都不属于应用层

题目问"哪些适合封装在底座、哪些属应用层"。答案必须拆成**两个维度**，否则会答错：

**维度一（方法论层）：10 SKILL 全部属于底座。** 依据是用户 2026-08-24 亲自立的去污染判据——`ai-*` 是**跨域通用方法论基线**，只承载通用洞察（法则/铁律/判据/模式），**零领域字面量**；凡出现 `IPD/PDM/P2P/Agent2b/RTM/DCP/Charter/SUPPLIER/MATERIAL/PROCUREMENT` 等域名专有词即视为污染，应外移 reference。

**因此：应用层 = 领域内容，不是"某几个 SKILL"。**
应用层清单（**永远不进底座**）：
- CRM 的 `HOST_BOM/HOST_PROTOTYPE/HOST_DEALER/HOST_PROJECT/HOST_ORDER/HOST_ASSET/HOST_WARRANTY/HOST_CHANNEL_STOCK/HOST_ATTACHMENT`
- 群诉的 `TICKET/EVENT/ENTITY/PLACE/CLUSTER`
- APS 的 `SLAB/UNIT/CASE/RUN/SOLUTION`
- PDM 的 Charter / RTM / DECISION 族
- 全部行业 HANDBOOK 实例、业务指标定义、审批域具体规则、组织与权限

### 3.2 维度二（物化层）：每个 SKILL 在底座里有两种物化方式

| # | SKILL | ① 运行期物化（进哪个包） | ② 设计期物化（脚手架提问） |
|---|---|---|---|
| 1 | `ai-ontology-vector-build` | `kernel/ontology` + `kernel/vector`：写时三钩子·contentHash 幂等·双 provider 降级·覆盖率监控·backfill | 问「哪些字段要语义检索」→ 向量化配置 + 覆盖率下限 |
| 2 | `ai-memory-lifecycle` | `kernel/memory`（experimental）：双轨·四闸门·蒸馏·分层检索·RRF·PII 护栏 | 问「要记住什么、先例从哪来」→ 记忆配置 |
| 3 | `ai-particle-system-design` | `kernel/ontology`：粒子/属性/受控谓词**运行时** | ★ 问「核心实体·生命周期·360°属性·关系」→ 粒子表+属性库+谓词 |
| 4 | `ai-context-layering` | `kernel/context`：L1–L4 装配·KnowledgeNeeds 供需编码·降级链 | 问「知识来源有哪些」→ 供给表 |
| 5 | `ai-native-action-design` | `kernel/actions`：Action Registry·R6 force 闸 | ★ 问「该域有哪些能力」→ R1–R6 推导 Action 清单 |
| 6 | `ai-multi-agent-orchestration` | `kernel/orchestration`：任务状态机·worker 派发·限流·熔断·僵尸任务·结果回收 | 问「哪些任务要派发」→ 编排 profile |
| 7 | `ai-portal-page-generation` | `chiyu-portal`：NL→PageSpec→唯一 HTML 出口 | ★ 问「角色·首页·导航」→ PageSpec 骨架 |
| 8 | `ai-event-driven-evolution` | `kernel/events`：事件总线·订阅者·进化判据（处方 PENDING，永不自动改红线） | 问「什么信号算异常、何时复盘」→ 事件与处方规则 |
| 9 | `ai-feedback-loop` | `chiyu-decision` 薄层：闸门与埋点骨架 | 问「北极星指标是什么」→ 指标与回路配置 |
| 10 | `ai-capability-audit` | `kernel/audit`：SHA-256 链·可证伪探针框架 | 生成项目自审清单与探针骨架 |

**推论：10 SKILL 在底座里是"双角色"资产**——既是运行时机制（进包），又是设计期问卷来源（进脚手架）。这正是"让其他项目少走弯路"的机制本体：**新项目不需要重新读 SKILL，只需要回答问卷。**

### 3.3 🔴 关键缺口：10 SKILL 覆盖不了决策脊柱

KMD 裁决时序（S1→S5）、九尺子 rubric、红线硬闸门、自主放行阈值 **不来自任何 SKILL**，来自**内置裁决规范·主链时序**（用户设计）。

- **10 SKILL 解决「平台能力」**：数据怎么建、记忆怎么存、任务怎么派、门户怎么生。
- **裁决主链规范解决「决策质量」**：什么时候必须拦、什么时候可放行。

**两者互补、不可互相替代。** 这从原理上证明了 D3 的合理性：`chiyu-decision` 承载底座里唯一"不可替代"的资产，因而必须**独立成包、独立授权**。

## §6 IP 双轨封装（回答问题 #2）

| 机制 | 落地方式 |
|---|---|
| **双轨构建** | `make dist` → 源码 wheel（内部项目）；`make dist-release` → Cython 编译 `.pyd` wheel（对外） |
| **同源校验** | 两轨 `contract/` 的 sha256 必须逐文件一致 → 防止双轨漂移成两套产品 |
| **授权分级** | `kernel`（基础）/ **`decision`（核心，最贵）** / `portal`（可选） |
| **离线授权** | 机器绑定 license 文件；⛔ **不上在线校验**——信创与参赛离线场景必须能跑（这也是 D3 让 L2 独立成包的真正动机） |
| **发布闸门** | `tools/verify_no_kernel_source.py`：扫描发布物，命中内核 `.py / .pyc / .pyd.map / Cython 中间产物` 即**硬失败**，纳入发布流水线 |
| **方法论保护** | 10 SKILL 完整正文**不随对外发布物分发**；对外只给「能力清单摘要」。⛔ 参赛交付物出现 SKILL 全文 = 方法论白送。`skills-manifest.json` 只登记版本与 sha256，不携带正文 |
| **诚实边界** | 编译**不是密码学保护**，只把逆向成本从"打开文件"抬到"逆向汇编"。护城河是「KMD 时序 + 九尺子判据 + 行业 know-how」，**方法论靠授权协议 + 知识产权安排**，代码编译只防"随手抄" |

### 6.1 ⛔ 由此产生一条硬编码规范（必须前置）

Cython 对动态特性敏感。若内核用了运行时造类 / `**kwargs` 动态派发 / `importlib` 反射，**后期编译不了只能重写**。故：

> **内核编码规范（P0 前置）**：① 禁运行时 `type()` 造类；② 禁 `**kwargs` 动态派发（显式签名）；③ 禁 `importlib` / `getattr` 反射式取函数；④ 契约类型用 `dataclass`/`pydantic` 静态声明；⑤ 新增内核模块须通过 `tools/check_cython_friendly.py` 静态检查。

## §10 风险与「不做」

### 10.1 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | **Cython 编译不可逆**：内核若含动态特性，后期编译不了只能重写 | §6.1 编码规范前置 + `check_cython_friendly.py` 静态检查纳入 T1 |
| R2 | **把未验证代码当底座**：demo 的记忆/粒子上层/Action 面未落地 | D4 方案 A：标 `experimental`，并在包文档显式登记（不伪装成已就绪） |

| R4 | **打断 demo 参赛交付节奏** | 底座仓库**独立**；demo 侧**只做接口对齐，不做代码搬迁**；抽取以 demo **只读快照**为起点，演示物不动 |
| R5 | **APS 变更面大**：9 份已批设计文档受影响 | §9 逐项列表 + APS 侧 RCR；建议 APS 侧先冻结新开发，等底座接口稳定 |

3. **不把 10 SKILL 正文放进对外发布物**。
4. **不在本设计内改 APS 代码**——本设计只出变更清单，改动须 APS 侧独立批准。
5. **不做常驻平台服务**（D1 已排除）。
