## 2. A-1 双写解锁路径（落点与验收判据）

### 2.1 落点：MCP sanctioned 面，禁 SQL 直写

CRM 镜像写 foundation `graph_edge` 的**唯一合法通道**是调用 `write_controlled_edges`——经 foundation MCP 服务端暴露为 write 类工具（risk="write"，走 A9 契约两阶段确认，与 CRM 现行零信任 confirm_token 流程同构）。**CRM 不得直连 foundation 库写 `graph_edge` SQL**：单源裁定守卫的裁定面是 foundation 仓源文件，跨仓 SQL 直写绕过闭集校验与悬空边拒绝，等于把双写退化为无守卫双写。

> ⚠️ **接线补正（T50）**：本回执初版 §2.1 所述 MCP 端点**当时为纸面**（`write_controlled_edges` 仅作库函数导出，未 `expose` 成可调用端点）。该缺口已于 T50 真实闭合——`chiyu_kernel.graph.mcp.build_graph_write_server(store, *, profile, auth, secret)` 经 `McpServer.expose(risk="write")` 暴露 `write_controlled_edges` 端点（两阶段确认 + 零信任鉴权内置），并有真库 E2E 证明其可调用（auth 拒绝 / 两阶段 / 真实落库 / 闭集经通道生效 / 令牌绑定）。CRM 现可实例化该 server（注入自身 `auth` + 自选 transport）拿到**真实可调用端点**。`build_graph_write_server` 已入 `chiyu_kernel.api`（sanctioned 面）。详见 §5。

## 5. 端点接线补正（T50：把"纸面通道"坐实为"可消费通道"）

### 5.1 诚实判定（用户 source-verify 抓出的缺口）
T48 初版 §2.1 称"A-1 唯一合法通道 = 经 foundation MCP 服务端调用 `write_controlled_edges`"——**当时为纸面**：
- `write_controlled_edges` 仅作 Python 库函数导出（`api.py` / `persist`），被单元/真库测试**直接函数调用**；
- 全仓**无任何生产代码**把 `write_controlled_edges` 注册成 `McpServer` 的 `risk="write"` 工具端点；
- ⇒ CRM 侧**没有可实际调用的 MCP 端点**，A-1 双写"缺的是已接线的调用端点，不是写能力"。

### 5.2 补正（已实现 + 已验证）
- 新增 `chiyu_kernel.graph.mcp.build_graph_write_server(store, *, profile=None, auth=None, secret=None)`：
  内部 `McpServer.expose("write_controlled_edges", handler, risk="write")`，handler 把 MCP 入参适配为 `EdgeWrite` 后调 `write_controlled_edges`；
  校验异常（`ValueError` 闭集/悬空）转结构化 `McpServerError`，禁把未处理异常抛给消费方。
- 导出入 sanctioned 面：`chiyu_kernel.api.build_graph_write_server` / `WRITE_CONTROLLED_EDGES_TOOL`。
- 参照 `examples/reference_consumer` 同构（能力包自带工具面），不发明传输层（R5：http/stdio transport 由消费方自实现，把请求喂 `McpServer.handle_request`）。
- 真库 E2E 证明：经该端点两阶段确认 → 真落库 `graph_edge` → `PgCteGraphStore` 只读视图读回（写读同表闭环）；闭集 `edge_source="consumer"` 经通道零落库。

### 5.3 部署边界（诚实）
"暴露"已闭合；**运行 server + transport 属消费方职责**（R5：真 transport 由消费方自实现）。CRM 拿到 `build_graph_write_server` 后：注入自身 `auth`（A9 契约）+ 选 transport（stdio/HTTP 喂 `handle_request`）即闭合 A-1 通道，**无需等 foundation 任何后续动作**。
