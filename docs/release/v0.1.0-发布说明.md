## 一、决策脊柱（chiyu-decision 0.1.0）

| 能力 | 说明 |
|---|---|
| **run_spine 全链** | S1 上下文 → S2 评分（九尺子）→ S3 八要素 → S4 红线 → 自主裁量 → S5 落库；`approval_gate` / `audit_sink` 注入点 |
| **审批闸 PENDING 三态**（B3 方案 Z） | APPROVED / REJECTED / PENDING（`.approved` 派生属性向后兼容）；pending 不落正边 + 审计留痕；**红线优先于闸裁定**——闸失职裁 PENDING 而红线命中时脊柱强制改判 REJECTED |
| **resume_spine 续跑**（G3 方案①） | 人工批准后只补 S5：不重跑 S1–S4、不重算置信度、不重判红线（"批的是甲、落的是乙"根治）；REJECTED 终态不可复活；幂等（二次 resume 零落库） |
| **评分符号独立授权** | `score_rubric` / `check_elements` / `autonomous_release` 等在 `chiyu_decision.api`——kernel 门面故意不含（D3 分层 + 授权分级），两包可独立 wheel 按需交付 |

## 三、质量与门禁升级（相比"拷 src"形态的核心增量）

| 门禁 | 判据 |
|---|---|
| 门面覆盖度 | 门面 import 了却没进 `__all__` 即红；每子包 LAYERS 登记 |
| sanctioned import 面 | 跨面导入即红（含本仓自身）；撞名清单非空且有建议 |
| §13 零残留 | `专利/N 件/实施例/权 x/7x7` 概念零残留（compileall 后含 .pyc） |
| 变异判别力 | 新增守卫全部做变异自证（删判据分支→转红→还原），本轮 ≥20 处 |

测试规模演进（同一组合口径）：515 → 737（+222，全部带守卫判据）；门禁判据放被调用方（脊柱层对**接线**变异，闸内分支变异不越位）。

## 四、交付物与升级步骤

```bash
pip install chiyu_kernel-0.1.0-py3-none-any.whl chiyu_decision-0.1.0-py3-none-any.whl
```

1. 启动代码加 `assert api_version() == "0.1.0"` + `require_capabilities([...])`（见使用指南 §1）；
2. 内部路径 import 全部改走门面（撞名符号全限定引用）；
3. `TIER_*` 别名迁移至 `VTIER_*`（下一版移除）；
4. PENDING 决策编排接入 `resume_spine`（审批单号传 `approval_ref` 供审计溯源）。

## 五、已知边界

- 回归套件为机制级 E2E（FakeStore/打桩 + 探针），**真库冒烟**建议部署窗口执行；
- `memory` / `evolution` 层 experimental：接口可能随验收调整（`capabilities()` 已显式标注），二者**均排除出 1.0 兼容承诺**——1.0 兼容仅覆盖 stable 能力层，BREAKING 须先走完整 deprecation 周期；
- ONNX 离线向量 4 例测试需先 `python tools/export_bge_onnx.py` 生成模型（环境基线，README 已注明）；
- MCP 真 transport（stdio 之外的 HTTP/SSE）未排期——消费方可按 `StdioTransport` 参考自实现，回馈即采纳。
