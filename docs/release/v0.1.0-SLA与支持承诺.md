# foundation v0.1.0 SLA 与支持承诺

> 适用对象：以 **wheel 分发**方式接入 `chiyu-kernel` / `chiyu-decision` 的消费方（APS / enterprise / CRM）。
> 版本：0.1.0 ｜ 日期：2026-10-09 ｜ 本承诺与 `docs/versioning-and-deprecation.md` 版本政策配合生效。
> 性质：底座为**随应用分发的组件库**（非在线托管服务），故本 SLA 分为「支持响应承诺」与「运行时 SLO 建议」两部分。

---

## 一、支持响应 SLA（缺陷分级）

| 级别 | 定义（判据可证伪） | 首次响应 | 修复或规避交付 | 说明 |
|---|---|---|---|---|
| **P0 致命** | sanctioned 面能力不可用（import 失败 / `require_capabilities` 通过但调用崩溃）；或红线/审批闸**结构失效**（redline_hit 未拦截落库）；或数据破坏（硬删除 / 决策重复落库） | ≤ 1 个工作日 | ≤ 5 个工作日（含补丁 wheel 或明确规避方案） | 涉及红线与数据完整性，最高优先 |
| **P1 严重** | 核心链路功能错误（run_spine 裁定错误 / persister 落库字段缺失 / resume 语义偏差），存在临时规避 | ≤ 2 个工作日 | ≤ 10 个工作日 | |
| **P2 一般** | 非核心功能缺陷 / 文档与行为不一致 / 性能回退（可量化） | ≤ 5 个工作日 | 下一例行版本 | |
| **P3 轻微** | 体验类 / 文档措辞 / 建议类 | ≤ 10 个工作日 | 排期评估 | |

**提交渠道**：缺陷报告须附**可复现实跑证据**（最小复现脚本 + `api_version()` / `capabilities()` 输出 + 期望 vs 实际）——与跨仓协作纪律同源：「以 `file:line` 反证，我方即改」。

## 二、版本与兼容性承诺

| 项 | 承诺 |
|---|---|
| **兼容范围（sanctioned 面）** | `chiyu_kernel.api` / `chiyu_kernel.contract`（含子树）/ `chiyu_kernel.approval` / `chiyu_decision.api` / `chiyu_portal.api` 的**符号级**兼容 |
| **版本策略** | stable 子集 semver：PATCH 向后兼容；MINOR 严格加法；MAJOR 才允许破坏。experimental 层（当前 `memory`）**不在兼容承诺内**，`capabilities()` 以 `experimental` 状态显式标注 |
| **弃用政策** | 先 **warn 一版**，再于下一版移除（在册样例：`TIER_* → VTIER_*` 别名）；移除前 CHANGELOG 显式公告 |
| **支持窗口** | 当前最新版 + 前 1 个 MINOR 版本（N-1）接收 P0/P1 补丁 |
| **破坏性变更通告** | MAJOR 升级前至少提前一个 MINOR 版本公告迁移指引 |
| **机械门禁背书** | 上述承诺由四道门禁机械执行（facade 覆盖度 / §13 零残留 / sanctioned import 面 / 变异判别力），非口头承诺 |

## 三、运行时 SLO 建议（供消费方上线参考）

底座自身为进程内组件，可用性取决于消费方宿主环境。以下为**建议消费方纳入其服务 SLA 的指标口径**，底座提供对应的自检/探针能力：

| 指标 | 建议口径 | 底座提供的支撑 |
|---|---|---|
| 决策链路健康 | `run_spine` 全链（S1–S5）可完成且审计留痕 | examples P1–P5 探针可直接改造为存活探针 |
| 落库一致性 | event 与 particle **成对**、engine 边恰好相等、红线命中挡落库 | `chiyu_kernel.canary.canary_probe` 三判据（不可判定一律 False，可作周期巡检） |
| 存储可用 | PG 连接经 `get_dsn`/`shared()`（禁指向未授权实例，`FORBIDDEN_HOSTS` 守卫） | `test_pg_isolation_guard` 同款判据可复用为启动预检 |
| 版本兼容 | 启动即 `require_capabilities`，未达标 fail-fast | G5 能力自检入口 |
| 审批续跑 | PENDING 决策经 `resume_spine` 续跑，REJECTED 终态不可复活 | 语义契约见回执 §二 |

> **消费方实测基准（APS，2026-10-09 实证窗口首采，来源《接入回执-APS-2026-10-09.md》§三）**：
> 便携 PG `chiyu_test` 单机、N≥6 区间口径——spine 决策全链 p50≈51.5ms（**S5_persist 落库段支配，占 ~96%**，S1–S4 合计仅 ~2ms，延迟预算应以落库为支配项评审）；persister 吞吐 ≈15.6 决策/秒（连续 20 决策，含建边+审计+校验）；图查询 `DECIDED_ON` 单边 p50≈1.57ms（图读面无瓶颈）。
> ⚠ 数值为消费方**单机基线**，不构成生产 SLA——生产宿主 + 并发负载下须重采（判据 §2-4 待办）。

## 四、安全承诺

- **零硬删除**：所有写入走墓碑语义，`assert_no_hard_delete` 机械拦截（含读路径 DROP）；
- **生产隔离**：`FORBIDDEN_HOSTS` 机制禁止测试/探针指向生产实例（`81.70.184.198` 类红线在库内拦截）；
- **MCP 零信任**：写类操作两阶段 confirm token（HMAC 绑定工具名+参数+主体），`auth=None` 一律拒绝；
- **口令不落盘**：DSN 口令仅运行态注入（env/参数），报错文案不回显口令。

## 五、免责与边界

- experimental 层（`memory` 记忆运行时的蒸馏策略阈值）接口可能随验收调整；
- 消费方**绕过 sanctioned 面**的内部路径 import 不受任何保护；
- 底座不含运维托管（PG 实例可用性属消费方/云服务商 SLA）。
