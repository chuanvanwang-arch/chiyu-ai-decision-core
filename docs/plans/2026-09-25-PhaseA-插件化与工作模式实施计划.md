# Phase A · 插件化与工作模式实施计划（对标 DeepSeek Harness 桌面版）

> 日期：2026-09-25 ｜ 状态：Phase A 已落地（确定性运行时）｜ 路线：先 A（模式借鉴落本仓）后 B（接 DeepSeek 真模型）

## 1. 背景与目标

来源文章（DeepSeek Harness 桌面版）给出三点可借鉴工程思路：

1. **四种工作方式**：标准 / PTC（Plan-Then-Code）/ 极简 / 创造。
2. **插件化架构**：6 个内置插件（终端、Agent 循环、Subagent、网页搜索、智能体团队、语音输入）。
3. **引导式页面导航**：登录 → 选工作区 → 选方向 → 选工作流 → 选工作模式。

用户目标（经 brainstorming 三段确认）：**C 分阶段**——先 A 把上述思路落到本仓
（`chiyu-kernel` / `chiyu-cli` / `chiyu-portal`），再 B 接 DeepSeek 真模型激活 LLM 驱动行为。
A 阶段范围已确认：**全插件化架构 + 四种工作模式全部纳入**（用户选 1234）。

## 2. 关键架构事实（约束）

- 本仓当前为**确定性运行时**：`chiyu-cli` 决策走确定性分支、不接真 LLM；
  `chiyu-decision.run_spine` 亦确定性。
- 故四模式中真正需要 LLM 驱动的行为（PTC「先写小程序」、创造「写插件」）在 A 阶段
  **只能以编排契约 + 双端入口 + 确定性桩**落地，B 阶段接进 DeepSeek 才被激活。
- 借鉴样板：CRM-ai-native 的 `seedActions()` 注册表 + `TenantProfile` 注入 + 粒子原型 +
  两阶段闸门，印证「注册表 + 注入 + 粒子原型」而非 manifest-JSON / entry_points。

## 3. 方案选定（方案 1：内核 PluginRegistry）

三套候选路线比对后选方案 1：

| 路线 | 结论 |
|---|---|
| 方案1 内核 Registry（code 模块） | ✅ 复用 `ActionRegistry` 范式 + 既有契约/校验/注入纪律，`pyc-only` 外部版天然兼容 |
| 方案2 manifest JSON | ❌ 无法表达 PTC/创造动态行为，与 code-contract 风格不统一 |
| 方案3 setuptools entry_points | ❌ 改打包、与 `pyc-only` 外部构建冲突、离线发现不稳 |

## 4. 架构映射（DeepSeek Harness → ChiYu）

| Harness 概念 | ChiYu 落点 |
|---|---|
| 四种工作方式 | `chiyu_kernel.plugins.WorkMode` 预设（standard/ptc/minimal/creative） |
| 6 个内置插件 | `BUILTIN_PLUGINS`：terminal(=chiyu-cli shell) · loop(=state_machine) · subagent(=idem/agent_registry) · web_search · team(=多agent) · voice(=输入适配器) |
| Everything is a Plugin | `PluginRegistry`：插件 = 一组能力槽位，模式 = 插件组合 + 编排开关 |
| 引导式页面导航 | `chiyu-portal.onboarding`：步骤与模式卡片从 registry/预设动态生成 |
| Phase B 真模型 | `llm/tier.py` 已预留 `deepseek-ai/DeepSeek-V4-Flash` 云端端点 |

## 5. 已实现（Phase A）

### 5.1 内核 `packages/chiyu-kernel/src/chiyu_kernel/plugins/`
- `contract.py`：`PluginSpec`(frozen dataclass，6 个能力槽位) + `PluginRegistry`(register/get/names/audit)。
- `builtins.py`：6 个对标插件，映射到既有内核能力（web_search/voice 在 A 阶段仅声明槽位）。
- `modes.py`：`WorkMode` + `MODE_PRESETS`(4) + `resolve_work_mode`(永不抛，未知/缺失回落默认并 warning)。
- `__init__.py`：导出。
- 接线：`api.py` 重导出全部插件符号；`tests/test_api_facade_covers_all_layers.py` 的 `LAYERS` 登记 `plugins`（否则 `test_no_undeclared_layer` 红）。

### 5.2 CLI `packages/chiyu-cli/src/chiyu_cli/`
- `commands/_plugins.py`：registry 装配 + 模式解析薄封装。
- `decide` / `portal render` / `shell`：加 `--mode`（从 `MODE_PRESETS`，未知模式给 warning 不崩）。
- 新增 `chiyu modes`（列出四模式 + 启用插件；`--mode` 看单模式详情）。
- `portal onboarding`：生成引导式导航 HTML 落盘/打印。

### 5.3 门户 `packages/chiyu-portal/src/chiyu_portal/`
- `onboarding.py`：`onboarding_steps()` / `mode_cards()` / `render_onboarding()`，菜单从 registry 动态生成。
- 经 `api.py` / `__init__.py` 门面导出。

### 5.4 测试与文档
- `packages/chiyu-kernel/tests/test_plugins.py`：注册/审计/模式解析/插件全注册/分区 等 13 例。
